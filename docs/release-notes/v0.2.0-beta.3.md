The third beta of **VoxRox Mail 0.2.0**, an e-mail client for Windows. It reaches installations that chose the **Beta** channel; everyone else stays on 0.1.0 until this version is promoted.

> **Closed beta.** Gmail signs in only with an account on the tester list. The application runs on Windows only for now.

> **From 0.2.0-beta.2 it updates on its own.** An installation of 0.2.0-beta.2 on the Beta channel offers this version through the updater. An installation of 0.1.0 or 0.2.0-beta.1 trusts only the retired signing key and installs this one by hand.

## Highlights

- The keyboard focus is easier to see: the selected command in the command palette and the focused item in every menu are outlined, not only faintly tinted
- The command palette works at 200% and 400% zoom and keeps the selected command on screen while you move through the list
- NVDA reads a checkbox or radio button on one line with its label, and more form fields carry the names a screen reader announces
- Going to Settings or elsewhere while Mail is still opening no longer pulls you back into the mailbox

All changes: [CHANGELOG.md](https://github.com/TheVoxRox/mail/blob/main/CHANGELOG.md)

## Install or update

On 0.2.0-beta.2 with the Beta channel chosen, accept the update when the application offers it, or choose **Zkontrolovat aktualizace** in **Nastavení → O aplikaci**. On 0.1.0 or 0.2.0-beta.1, run the installer over your installation. Either way it keeps your mail, accounts and settings and needs no administrator rights. Going back to an older version afterwards is not possible: the installer refuses it.

The installer is not signed, so Windows reports an unknown publisher. Before running it through **More info → Run anyway**, verify the downloaded file as [END_USER_README.md](https://github.com/TheVoxRox/mail/blob/main/frontend/END_USER_README.md) describes. How releases will be signed: [Code signing policy](https://github.com/TheVoxRox/mail/blob/main/CODE_SIGNING_POLICY.md).

## Known issues

- Gmail signs in only with an account on the tester list (see the closed beta note above).
- An occasional transient failure to connect to the IMAP server. Sync recovers on its own in the next cycle, and no mail is lost.
- A mail server that sends extremely large answers can still make the mail service run out of memory when two such accounts sync at once; it then restarts on its own. No data leaves your computer. If that happens three times in a row, the sync of that account pauses until you choose **Synchronizovat**.
